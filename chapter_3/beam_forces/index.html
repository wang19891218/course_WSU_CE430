Under the hood — the physics engine

This page is not a canned animation. Every frame, it integrates the dynamic Euler–Bernoulli beam equation

m ∂2v/∂t2 + damping + EI ∂4v/∂x4 = q(x, t)

Which engine? A purpose-built one: beam_solver.js, about 200 lines of dependency-free JavaScript written for this course. Off-the-shelf game physics engines (Matter.js, Box2D, Rapier) simulate rigid bodies and cannot represent continuous bending quantitatively — so this page solves the real beam equation instead.

How it works, each time step:

  1. The beam is divided into 200 segments (201 nodes), each carrying mass and a deflection v.
  2. At every node the bending force is computed from the fourth derivative of the current shape, EI ∂4v/∂x4, using a 5-point finite-difference stencil — plus strain-rate damping and your applied loads q(x).
  3. Supports are constraints: a fixed end prescribes both position (settlement Δ) and slope (rotation θ); a pinned end prescribes position and sets the end moment to zero.
  4. Velocities and positions are updated by symplectic Euler integration. Bending stiffness makes the system numerically “stiff,” so each animation frame is split into thousands of tiny stable substeps (live count below).
  5. The forces you see are read off the shape: M = −EI v″, V = dM/dx, reactions from the end shears.

The dashed blue curves come from a second, independent solver in the same file: the exact closed-form static solution of the same equation (∂2v/∂t2 = 0). The simulation settling onto it — every time, for every input — is the engine's ongoing self-check.
